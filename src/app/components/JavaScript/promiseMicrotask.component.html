Lets understand the chains interleave

What is the output and Why

{{ codeBlock1 }}

The output is:


    1
    3
    2
    4

Why?

Promise.resolve() creates an already-fulfilled promise, but .then(...) callbacks are always scheduled as microtasks and do not run immediately.

Let's walk through it.

Initial synchronous execution

    
        let promise1 = Promise.resolve();
        let promise2 = Promise.resolve();

Both promises are already fulfilled. Then:

    
        promise1
            .then(() => console.log(1))
            .then(() => console.log(2));

The first .then(() => console.log(1)) is attached to an already-fulfilled promise, so a microtask is queued to run console.log(1).

The second .then(() => console.log(2)) is attached to the promise returned by the first .then(). That returned promise is not fulfilled yet, so nothing is queued for 2 yet.

Similarly:

    
        promise2
            .then(() => console.log(3))
            .then(() => console.log(4));

Queues a microtask for console.log(3). The callback for 4 waits for the promise returned by the previous .then().

At the end of synchronous code, the microtask queue contains:

[ log(1), log(3) ]

Processing microtasks

Microtask 1: log(1)
1

When this callback completes, the promise returned by the first .then() becomes fulfilled, which queues the next callback:

Queue: [ log(3), log(2) ]
Microtask 2: log(3)
3

Its completion fulfills the next promise in that chain, queuing log(4):

Queue: [ log(2), log(4) ]
Microtask 3: log(2)
2
Microtask 4: log(4)
4

Mental model

Think of each promise chain as:

    
        promise1: 1 → 2
        promise2: 3 → 4

The first callbacks (1 and 3) are queued immediately. The second callbacks (2 and 4) can only be queued after their preceding callback finishes. Because microtasks are processed FIFO, the chains interleave:

1, 3, 2, 4
